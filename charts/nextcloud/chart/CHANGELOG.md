# 0.3.0

Published on 21 October 2026

- Login with Emporium: the `sso` OIDC integration and the official `user_oidc` app. A before-starting hook installs the app from the Nextcloud app store (it is not in the image) and creates or updates the provider "Emporium" on every start; the login page gets a "Login with Emporium" button. The client secret is read by reference and handed to `occ` through the environment (`--clientsecret-env`), never as an argument. Without the app store or the OIDC settings the hook logs a warning and Nextcloud starts with the local login only.
- Callback `/apps/user_oidc/code` (also registered with `/index.php`). Logout ends the Nextcloud session only (`single_logout` off: no post-logout redirect is registered at Logto).
- Accounts: an Emporium login creates a Nextcloud account whose user id is the Logto user id (`sub`, no hashing), with the display name from `name` (fallback `username`) and the email. `soft_auto_provision` is off, so an Emporium login never signs in to an existing local account: if a local account has the same id, the login is refused ("User conflict"); if the setting cannot be applied, the hook does not configure the provider. Existing local users get a new, empty account on their first Emporium login; move files with `occ files:transfer-ownership <old-user> <new-user-id>` if wanted.
- The local login stays available (the admin from "Admin username" is the break-glass account). Admins are granted in Nextcloud (Users > group `admin`): `user_oidc` can only create groups named like the Logto roles (`emporium-admin`), not map them to Nextcloud's `admin` group, so group provisioning is off.
- Fix: a new install failed and never recovered. The image runs `occ maintenance:install` (and upgrades and hooks) as `su -p www-data` with `HOME=/root`, and libpq stopped at the unreadable `/root/.postgresql/postgresql.crt`; the next start found the copied files and skipped the install, leaving Nextcloud "not installed". `PGSSLCERT` now points to a path that does not exist (no client certificate). An instance stuck in that state: see MIGRATION.md.
- Fix: the ingress answered 500 for the whole host on clusters whose ingress rejects a body size limit above 4 GiB (`proxy-body-size: 5000m`). The limit is now `0`: no ingress size cap (Nextcloud's own upload limits, chunking and quotas still apply).
- Catalog category is now Productivity (was Utilities).
- Nextcloud stays on 35.0.2 (nextcloud chart 9.4.1), the latest upstream release.

# 0.2.0

Published on 20 October 2026

- Requires Emporium v0.5.0 (`emporium.yaml`). PostgreSQL stays the `postgres` postgres integration (CloudNativePG cluster `<release>-postgres` as in 0.1.0, PostgreSQL 17); libpq connects with `PGSSLMODE=require`.
- Redis is the `redis` integration (Valkey, persistent, no eviction) instead of the bundled Bitnami Redis master with three replicas; the password is read by reference from the app's Secret. Nextcloud uses it for transactional file locking and the distributed cache.
- The admin account ("Admin username", "Admin password") is read from the per-app Secret; the password is generated when left empty. The chart's own `nextcloud-admin-credentials` and `nextcloud-redis` Secrets (random values regenerated by Helm) are gone.
- Optional SMTP: host, port, user and sender come from the `mail` integration, the password by reference from the app's Secret.
- Data volume (`/var/www/html`) is the `data` storage integration (20Gi default, grow-only) instead of the StorageSize field and the chart-created claim, so the uninstall keep/delete choice applies.
- Ingress host, TLS secret, ingress class and annotations come from the `web` ingress integration; sync clients (WebDAV, OCS, login flow v2), public shares and `.well-known` discovery are `skipPaths`. The literal `kubernetes.io/tls-acme` annotation is gone.
- Background jobs run every 5 minutes in a cron sidecar (were AJAX on page loads); default resources for Nextcloud and the cron sidecar; a startup probe covers the first-start installation.
- nextcloud chart from 9.4.0 to 9.4.1, Nextcloud from 35.0.1 to 35.0.2.

# 0.1.0

Published on 19 October 2026

- New installs use PostgreSQL from Emporium's native Postgres integration (CloudNativePG, PostgreSQL 17); credentials come from the CloudNativePG app secret. Requires Emporium v0.5.0.
- The bundled Bitnami postgresql subchart is disabled. It was never used: the internal SQLite database stayed enabled, so existing installs ran on SQLite. They keep using it, because Nextcloud reads the database type from its persisted config.php.
