# 0.3.0

Published on 20 October 2026

- Requires Emporium v0.5.0 (`emporium.yaml`); PostgreSQL is the `postgres` integration (CloudNativePG cluster `<release>-postgres` as in 0.2.0, PostgreSQL 17).
- Redis is two Emporium redis integrations (Valkey, persistent) instead of the bundled Bitnami redis subchart: `redis` for the cache and `queue` for the Celery broker (`AMQP_URL`), so Plane needs no RabbitMQ and the API's cache flush at start-up cannot wipe queued tasks. The URLs are read from the per-app Secret.
- Uploads are Emporium's `uploads` object storage integration (RustFS, bucket `uploads`) instead of the bundled Bitnami minio subchart. Existing uploads are not carried over.
- Fixed: the chart did not start with Plane v1.4.2. The web and space containers used a start script the v1 images no longer ship, the API used `./bin/takeoff`, and Celery had no broker. The chart now follows Plane's own layout: separate api, worker, beat, web, space, admin (`/god-mode`) and live (`/live`) workloads, and a migration Job.
- Fixed: `/spaces` went to the API service; it now reaches the space app.
- The Django secret key and the live-server key are generated inputs in the per-app Secret (the key was regenerated by `randAlphaNum` before). The SMTP password is read from the per-app Secret instead of plain values.
- Ingress host, TLS secret, ingress class and annotations come from the `web` ingress integration; access defaults to admins so only an Emporium admin can claim Plane's instance admin at `/god-mode`; relax it to authenticated after setup. `/api/v1/*` (API-key access) skips the login.
- New input "Allow sign-ups" (off by default; sign-ups were always on before).
- Resources and replicas per component; profiles small and medium.

Existing data in the bundled database is not migrated.
