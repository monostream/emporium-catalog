# neuvector 0.0.x -> 0.1.0 (Emporium 0.5)

## Removed and renamed inputs

| Old key | New key | Note |
|---|---|---|
| `StorageSize` | deleted | `data` storage integration (default 10Gi, grow-only; was 20Gi). |
| `PersistenceStorageClass` | deleted | Storage class is chosen on the `data` storage integration. |
| `EnableFederation` | deleted | It published `neuvector-master.tribbles.cloud` / `neuvector-managed.tribbles.cloud`, which only worked on one cluster. Federation is not offered in 0.1.0. |

## Database

None. NeuVector backs up its configuration to the controller volume (`CTRL_PERSIST_CONFIG`).

## Data volume (keep it before uninstalling 0.4)

The upstream chart creates the claim `neuvector-data` **without** `helm.sh/resource-policy: keep`.
Before uninstalling a 0.4 release, annotate it:
`kubectl -n <ns> annotate pvc neuvector-data helm.sh/resource-policy=keep`.
Then move the instance with the installed-app blueprint
(`docs/blueprints/migrate-installed-app-to-v0.5.md`) and choose `neuvector-data` as the existing
claim. Without the volume NeuVector starts with default policies.

## Hostnames

No extra hosts (federation hosts removed, see above).

## TLS secret

`<release>-tls` became the integration's `TLSSecretName` (zone dependent: `<release>-tls` in
perHost mode, `emporium-wildcard-<zone>` in wildcard mode).

## Secrets

- OIDC client secret: **plaintext** in the chart's `neuvector-init` Secret (and the Helm release),
  because NeuVector reads OIDC settings only from `oidcinitcfg.yaml`. Lint warning
  `plaintext-secret-output` accepted.
- Admin password: generated by the NeuVector controller into `neuvector-bootstrap-secret` on first
  start (key `bootstrapPassword`). A migrated controller volume keeps the existing admin password.
- The upstream chart still uses Helm `lookup` for its internal certificates: no manifest diff in
  preview.

## Cluster-scoped objects (one install per cluster)

NeuVector cannot be installed twice in one cluster, whatever the namespace:

- Fixed-name ClusterRoles and ClusterRoleBindings `neuvector-binding-*`, nine CRDs
  `nv*.neuvector.com` (rendered as templates, so Helm deletes them and every NeuVector rule CR on
  uninstall), admission and CRD validating webhooks.
- The enforcer DaemonSet runs privileged on every node with host PID, host paths and the
  containerd socket (`/var/run/containerd/containerd.sock`); namespaces enforcing the
  `baseline`/`restricted` Pod Security level reject it. Its footprint is multiplied by the node count.
- A second install, or an existing NeuVector, fails on the name conflict (Helm refuses objects owned
  by another release). `requiredCRDs` does not apply: the chart ships its own CRDs.

## Behaviour changes

- OIDC users get the `reader` role; promote users in the NeuVector console (the stale
  `authentik Admins` -> admin group mapping is gone). `always_reload` stays on, so OIDC settings
  edited in the console are reset to the Emporium client on restart.
- `leastPrivilege: true` (dedicated ServiceAccounts), plain HTTP console behind the ingress.
- The chart no longer writes `emporium.build/auth-*` or `kubernetes.io/tls-acme` annotations, and
  `oidcRedirectPaths` left `Chart.yaml`.
