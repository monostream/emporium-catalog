# PhotoPrism

[PhotoPrism](https://www.photoprism.app/) is a self-hosted photo library. It indexes photos and videos from your own storage, labels them with built-in image classification, recognises faces, shows them on a map and in a timeline, and shares albums by link, without handing your pictures to a cloud service.

## What you get

- Library with search, albums, labels (automatic classification), people, places and calendar, RAW and video support.
- Two volumes: **originals** (your photos and videos, default 50 Gi) and **storage** (SQLite database, thumbnails, cache and sidecar files, default 10 Gi). Both can grow, not shrink.
- Single sign-on with your Emporium account; Emporium administrators become PhotoPrism administrators, other Emporium users are guests.
- A local administrator for emergencies, with a generated password.

## Good to know

- **Community Edition.** The image is the official `photoprism/photoprism` build, AGPL-3.0, free to self-host. PhotoPrism sells Plus (membership) and Pro/Enterprise editions; the Community Edition has everything described here but lacks the Pro features (user management UI and API, roles beyond admin and guest, session monitoring, audit log, the generic HTTP request limiter).
- **Database: SQLite, one instance.** PhotoPrism has no supported PostgreSQL mode in this release (MariaDB is the upstream recommendation, PostgreSQL is a development preview). The chart uses SQLite on the storage volume, so there is exactly one replica and indexing gets slower for libraries of several hundred thousand files. A MariaDB option is not part of this chart.
- **Access: PhotoPrism's login is the gate.** The ingress is **public**: there is no Emporium login in front of PhotoPrism. PhotoPrism has its own login (local accounts, app passwords, OIDC), and its share links are meant for anonymous viewers; a share link redeems its token through the same session endpoint as the password login and then loads the web app and its API, so no path-based Emporium login can protect the rest without breaking shares. Public mode is off (`PHOTOPRISM_AUTH_MODE=password`): every request to the library needs a login or a share token. PhotoPrism limits failed logins (burst of 10, then one attempt per minute, for sessions and for WebDAV; verified: the 11th wrong login answers 429); it does not have the generic HTTP request limiter. The local administrator password is generated (24 characters).
- **Single sign-on with Emporium is the recommended login.** Use "Continue with Emporium" on the login page (or switch on "Sign in automatically": after signing out, or when the round trip fails, PhotoPrism shows the login form once). Accounts are created at the first sign-in and named like the Emporium username. The ID tokens Logto signs with ES384 are accepted.
- **Admin role: promoted by Emporium, demoted by hand.** The `roles` claim is mapped with `PHOTOPRISM_OIDC_GROUP_ROLE=emporium-admin=admin`: a member of the Emporium role `emporium-admin` is a PhotoPrism administrator from the sign-in on, whatever order the provider lists the roles in (there is a single mapping, so the first match is the only match; verified live for an admin with both roles, assigned in either order). There is deliberately **no automatic demotion**: PhotoPrism changes the role of an existing account only when a mapping matches, and a second mapping (`emporium-user=guest`) would depend on the order in which the provider lists the roles, which is not guaranteed. When `emporium-admin` is removed from someone, their PhotoPrism account keeps the administrator role until you demote it: `kubectl -n <namespace> exec deploy/<release>-photoprism -c photoprism -- photoprism users mod --role=guest <name>` (an open session keeps its role until the next sign-in).
- **Roles of new accounts.** Community Edition knows only `admin` and `guest`. New single sign-on users who are not Emporium administrators get the role "Role of new single sign-on users" (default **guest**: they see only albums that were shared with them and can react to them, not the library). Set it to `admin` only if every new identity may manage the whole library; changing it later does not change existing accounts.
- **Local administrator.** The account `photoprism-admin` (name configurable at install) is created from the generated password at the first start; the password is in the app's Secret (command in the install notes). The password input only takes effect for an empty database.
- **WebDAV.** `/originals/` and `/import/` use Basic authentication with an app password or the account password (anonymous: 401). Only administrators can use WebDAV in Community Edition (guests have no WebDAV permission). The install input "WebDAV for new single sign-on accounts" is only the default for accounts created at their first sign-in: enabling it later does not grant existing accounts access and disabling it does not revoke it. Change a single account inside the pod with `photoprism users mod --webdav=true <name>` or `--webdav=false <name>` (flags before the name; Community Edition has no user management in the web UI; verified) and revoke an app password under Settings > Account > Apps and Devices. If you do not sync via WebDAV, leave the default off.
- **Share links** (Albums > Share) work for anonymous visitors; set a password or an expiry on the link if the album is sensitive.
- **Indexing is CPU and memory heavy.** The image classifier and face detection run on the CPU. The default profile requests 500m CPU and 1 Gi and limits memory to 3 Gi; "Indexing workers" defaults to 2 (a smoke test with 14 photos peaked at about 700 MiB). Raise the workers only with a larger profile. No GPU.
- **Telemetry.** PhotoPrism's usage info is off by default and the chart does not enable it.
